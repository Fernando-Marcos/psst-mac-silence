# Psst 1.5.2 — Restauración más segura y CI blindada

Versión de seguridad y fiabilidad sobre 1.5.1: la interfaz y los tres modos (Biblioteca, Concentración y Ultra Focus) funcionan exactamente igual.

## Novedades

- **Restauración por UID.** Core Audio reasigna los identificadores de dispositivo al reiniciar o reconectar salidas. Psst guarda ahora el UID persistente de cada salida y solo restaura el volumen en esa misma salida. Las instantáneas de versiones anteriores siguen funcionando: se aplican únicamente si el dispositivo sigue conectado.
- **Salidas desconectadas.** Si unos cascos silenciados ya no están al desactivar, Psst restaura el resto y te lo indica.
- **Nunca sin vuelta atrás.** Si no puede guardar tu volumen actual, Psst no silencia nada.
- **Instantánea validada.** El archivo de restauración tiene un tamaño máximo, sus valores se acotan (volumen 0–1, mute 0/1, canales y dispositivos limitados) y se guarda con permisos solo para tu usuario, dentro del contenedor de App Sandbox.
- **Silencio sin picos.** Primero se aplica el mute y después el volumen cero.
- **Una sola instancia.** macOS impide abrir Psst dos veces, lo que evitaba que dos copias se pisaran el volumen guardado.
- **Versión siempre correcta** en "Acerca de Psst", leída del propio bundle.

## Seguridad y límites

Psst sigue dentro de App Sandbox, con Core Audio público como única vía de control de audio y sin entitlements adicionales. Lo nuevo es que ahora se comprueba de forma automática:

- `Scripts/check-privileges.sh` falla si el código usa procesos, AppleScript, Apple Events, red, escalada de privilegios o IOKit, o si la app firmada tiene algún entitlement distinto de App Sandbox o le falta Hardened Runtime.
- La CI fija las acciones de GitHub por hash, no conserva credenciales, escanea secretos con Gitleaks, ejecuta las pruebas XCTest y publica la suma SHA-256 del ZIP.

La firma sigue siendo ad hoc: demuestra la configuración del sandbox, pero no sustituye a Developer ID ni a la notarización de Apple.
